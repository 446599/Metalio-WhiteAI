# 当前缺陷与优化计划

审查日期：2026-09-18。范围：当前工作区的 raw UI、AI 会话、胶囊保存、数据服务、字体和构建交付。本文是实施计划，本次未修改产品代码，也未烧录设备。

当前可继续开发，但尚不适合当作已完成验收的产品版本交付。先处理构建可复现、会话隔离和保存语义，再处理体验和功能扩展。

- 本次重新执行 `check_ui_contract.py`、`check_ai_contract.py`、`check_full_font.py`，均通过。字体包 45,248 字符、4,328,412 字节。
- 在临时目录编译真实 `PercentValue` 函数，并在现有 AI 主机测试外壳中注入审查用事件，复现了额度换算、保存状态和旧 session 消息接收问题；未改写仓库测试。

## 缺陷清单

### F1 · P1 · 仓库无法完整复现当前本地构建

证据：`main/CMakeLists.txt:72` 要求 `reader_text`；`.gitignore:2` 忽略 `components/*`，未放行 `components/reader_text`；该组件没有被 Git 跟踪。根 CMake、AI 实现等必要文件也还未提交。`dependencies.lock` 被忽略，同时依赖清单含通配符和版本范围。

影响：当前机器上的构建成功依赖未入库文件；提交现有 tracked diff 仍不能得到完整工程，重新解析依赖也可能得到不同版本。

改进：确认需要维护的源码和第三方组件边界，修正忽略规则，纳入必要源码及依赖锁定文件；构建目录、旧备份和无关演示文件不进入发布源码。保留一个当前可构建的基线后分批修复。此阶段不自动删除历史文件。

验收：在全新目录中，仅用已纳入版本控制的源码和明确声明的依赖，完成配置、构建、三项检查；不读取原工作区的 `build`、隐含本地组件或缓存产物。

### F2 · P1 · 完整字体没有进入标准烧录清单

证据：`raw_font::Init()` 从 `font_data` 分区读取；`partitions/v1/16m.csv` 定义该分区；当前 `build/flash_args` 只有 bootloader、分区表、OTA 初始数据和应用，没有 `assets/fonts/harmony_full.fontpack`。构建脚本也未注册字体烧录步骤。主机预览则直接载入本地字体包。

影响：新板按文档执行标准烧录后，完整字体不会随之写入，动态文本可能退回有限内置字体和缺字方框；主机预览正常不能证明板上字体已部署。

改进：提供包含应用、分区表、字体哈希与版本的发布清单；明确区分首次部署和保留 NVS 的应用更新。字体地址从已验证分区表读取，提供写入与读回校验步骤；设备暴露字体就绪状态和版本。不要把刷写分区表无条件并入普通应用升级。

验收：空字体分区、错误字体包和正确字体包三种状态均可识别；在测试板完成完整部署后，字体计数和哈希符合发布清单，繁简及生僻字实屏可见。

### F3 · P1 · 对话响应缺少有效的跨轮隔离

证据：`xiaozhi_client.cc:506` 的接收逻辑以 `accept_response_` 布尔值控制；除 hello 外没有校验消息的 `session_id`。`intent_generation_` 只用于本地发送意图，没有绑定到响应接收。现有测试只验证取消后、下一轮尚未开放接收时的迟到消息。

复现：取消旧轮，完成下一轮按下/松开，再注入带 `session_id="old-session"` 的 STT，旧文本被写入当前原文。

影响：重连或快速开启下一轮时，迟到文本可能污染新胶囊；旧 TTS 事件也缺少轮次归属保护。真实服务端是否出现该交错仍需集成测试。

改进：由单一会话状态机拥有连接代次、会话和当前轮次；校验协议实际提供的标识。协议缺少轮次标识时，明确选择受支持的中止完成屏障、等待旧流结束或必要时重建会话，不能仅添加一个本地计数器就声称解决接收隔离。对二进制音频使用相同生命周期控制。

验收：取消 A 后发起 B、旧 session STT、旧 TTS start/stop、断线后旧回调均不会修改 B 或播放旧音频；短按、松手竞争和正常对话原有检查仍通过。

### F4 · P1 · “已保存”不代表当前显示内容已持久化

证据：`xiaozhi_client.cc:558` 在 STT 时排队保存，TTS 完成分支没有补存；`conversation.cc` 的 `ReceiveAnswer()` 不清除 `saved`，`MarkSaved()` 只匹配 turn，不能区分同一轮的不同内容版本。UI 根据这个布尔值显示“已存 · 再保存”。

复现：保存原文后追加回答，`saved` 仍为 true；加载最近胶囊后回答长度为 0。原文自动保存本身符合当前文案，缺陷是它与“当前整条胶囊已保存”的状态混为一谈。

改进：区分原文已保存、回答未保存、保存中、失败；引入内容 revision 和 persisted revision，异步提交只能确认它保存的版本。保留 STT 后原文自动保存，并在回答完成时补存最终内容。存储结构增加 schema 版本，并评估共享 16 KiB NVS 的剩余容量；如不足，迁移方案须明确保留原有配置和胶囊。

验收：保存后回答继续增长时重新显示待保存；完成后重启能恢复原文和回答；模拟 commit 失败不显示成功；新轮不会被旧保存完成通知标记为已保存；在真实 NVS 接近满容量时验证错误反馈。

### F5 · P1 · 额度单位推测导致严重误显示

证据：`dashboard_service.cc:80` 将所有 0..1 的值乘以 100；`FetchQuota()` 已将 `used_percent` 转为 0..100 的剩余百分比，随后仍调用该函数。

复现：使用率 99% → 剩余输入 1.0 → 显示 100%；使用率 99.5% → 剩余输入 0.5 → 显示 50%。

改进：每种已支持的接口字段明确标注单位，比例和百分数分别解析；先验证范围再转换，拒绝不明确的字段映射。首轮只修正现有已支持格式，实际额度网关接入单独验收。

验收：覆盖 used=0/1/98/99/99.5/100，以及缺字段、负数、超范围、非有限数；确认百分数 1 与比例 1 含义不同，按 schema 解析。

### F6 · P2 · 离线缓存没有显示时效

证据：天气、额度都有 `updated_epoch`，但 `raw_display.cc` 没有消费该字段；缓存恢复时仍直接设为 valid。

影响：断网或接口长期失败后，旧天气/旧额度仍可能被当作当前数据理解。

改进：分开表达有无数据、请求状态和数据新鲜度；显示上次更新时间或过期提示。过期阈值按数据源定义，系统时间未校准时显示时间未知，不伪造新鲜状态。

验收：冷启动无缓存、缓存有效、缓存过期、断网、请求失败和时钟未同步都有明确且一致的显示。

### F7 · P2 · 触摸任务与屏幕刷新耦合，异步操作反馈不足

证据：`TouchTask()` 直接调用触摸/导航处理，处理路径会持显示锁调用 `FlushLocked()`；该函数等待面板完成，刷新后等待超时上限为 15 秒。AI 硬件键已把视觉工作排队，但内容触摸没有统一采用该策略。`RunQuickAction()` 忙碌时返回 false，调用方丢弃返回值，按钮仍维持可操作外观。

影响：刷新期间触摸轮询可能暂停，连续操作容易丢失；忙碌时点击快捷操作没有明确反馈。尚未测量实际延迟，不能将 15 秒超时当成正常刷新时间。

改进：输入任务只采集并提交有界事件，由 UI 任务更新状态；合并重复绘制请求，保留最后一个需要显示的状态。屏幕刷新由单一执行路径负责，维持现有面板历史缓冲不变量。使用静态忙碌文案和禁用态，避免在墨水屏上引入持续动画。

验收：记录触摸采集到入队、按键松开到停采集、刷新耗时分布；建议输入入队及松手停采集 P95 <100 ms，正式阈值以首轮实测确认。连续点按、AI 流式回答、全刷和超时恢复时队列有界，麦克风停止不等待显示。

### F8 · P2 · 文档、产品入口和测试边界不一致

证据：README/UI 契约仍说明 BOOT 确认和点击 AI 开始聆听，但板级 `InitializeButtons()` 已将 BOOT 绑定到按住说话；阅读页仍是三页硬编码示例；文档把随手记描述为演示流程，实际已加入最近胶囊保存。主机 AI 测试通过提取部分方法和模拟组件运行，不覆盖完整任务调度、真实 NVS 容量和网络交错。

改进：从实际路由生成或统一维护操作说明；给尚未实现的入口明确边界，优先完成“说话 → 整理 → 保存 → 恢复”这一条主路径。补充上述确定缺陷的回归测试和少量真机端到端验收，避免继续扩大演示页面数量。

验收：文档与实际按键、页面文案一致；每项宣称“已验证”的能力都能关联主机检查或真机记录，并注明证据类型。

## 结构优化与回归策略

- `raw_display.cc` 当前 4,163 行，混合产品绘制、输入路由、串口协议、面板波形和诊断。完成行为回归后，按输入路由、产品页面、面板刷新、诊断接口拆分职责；先固定接口和状态所有权，再移动代码，避免只把大文件搬成多个同样耦合的文件。
- `xiaozhi_audio.cc` 当前 1,233 行。产品音频会话与自检代码应有清晰边界；暂不为此重写稳定的编解码和重采样路径。
- 会话单元测试覆盖状态迁移；存储测试覆盖内容版本、真实容量和失败；少量任务级集成测试覆盖取消/重连/迟到事件；绘制检查覆盖字形、文本和命中区。避免只断言源代码字符串存在。
- 实机首轮验收：至少 20 轮短句/长句/快速取消/新轮打断，检查是否串话；离线再恢复；保存完成后重启；字体缺失与正确部署；记录堆、栈、收发计数、输入延迟和刷新耗时。日志保留统计和事件类型，不保留 token 或私人对话正文。
- 延迟、残影、续航都先测量基线，再定优化目标；不以软件预览或编译成功代替实物结论。
