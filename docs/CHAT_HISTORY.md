# 小智快捷任务、本地历史与笔记布局

基线：`349dd43`（用户已验证正常的音频版本）。本次不改音频任务栈、BLE 默认开关、USB、字体、分区、NVS 笔记格式或刷新波形。

## 快捷操作为什么以前失效

旧 `RunQuickAction` 将提示词和整段原文塞进 `listen.state=detect.text`。上游维护者已说明 detect 是简短唤醒词/事件接口，不能当作任意长文本聊天接口（78/xiaozhi-esp32 issue 1327）。此版保留文档支持的短事件，不猜测一个未实现的 `type:text` 接口。

点击整理灵感/待办草稿/翻译英文后，设备冻结完整任务，发送对应短事件，并提供 `self.chat.get_task` 只读 MCP 工具。模型按 `next_offset` 分页读取真实原文后处理。已读完任务才接收本轮结果，避免把唤醒问候当成翻译成功。未读取、服务拒绝、断网和超时明确显示错误；原文及历史保留。连续操作至少间隔 10 秒，不规避服务端自己的速率限制。

工具只暴露当前用户明确触发的任务，不允许文件路径、任意历史查询或凭据读取。切换/取消/断开使旧任务失效；继续历史聊天仅显式提供最近两轮的有界摘要上下文。任务文本和历史都是用户数据，不应当作系统指令。

设备工具从 26 变为 **27 个、9 页**。服务端必须启用设备 MCP、完成所有工具页发现，且角色应允许读取设备任务。新工具置于系统工具前列。固件升级后重连以刷新工具发现。某些自建服务也支持文本输入，但此版本不假定该扩展通用于官方服务。

若服务仍不调用工具，将下面说明加入小智角色介绍（这不是修改固件或设备联网凭据）：

> 收到“整理灵感”“待办草稿”“翻译英文”“文字提问”或“继续对话”事件时，先调用 self.chat.get_task，从 offset=0 开始，使用返回的 task_id 和 next_offset 读取至 complete=true。再处理 operation 和 text 中的用户请求。不要用唤醒问候代替结果，不猜测未读到的原文。待办只生成草稿，除非用户另外明确要求，不自动创建提醒或执行任务。

主机协议测试能验证消息、状态和 MCP 分页，不能证明某个实际云端模型一定调用工具；需用设备完成一次三项快捷操作验收。

## 类似聊天应用的本地历史

小智页顶部新增“输入 / 历史 / 新建”。每轮识别到原文后自动写入 pending 记录；正常回答结束保存 complete，取消/错误保存中断状态。每轮问答保留原文、回答、快捷操作类型、时间及截断标志，而不是只保存三行摘要。

历史列表按最近更新时间排序，点选打开用户/助手消息，支持文本翻页、上一轮/下一轮、继续对话和确认删除。新建会话断开旧云端会话，防止串话。重启后历史仍可查看，默认新的语音属于新会话；继续历史会重新建立云端连接，并通过同一个任务工具恢复最近两轮片段，不声称恢复服务器内部完整会话。恢复上下文有长度限制，UI 标明不是全量历史。

保存目录：`/sdcard/chats/00000001/00000001.0` / `.1`，会话和轮次都使用固定数字编号。每轮独立双槽 CRC、fsync、读回验证；目录是索引，不在 NVS 放全部聊天。无额外长期 RTOS 工作栈，复用现有小智网络任务处理 SD，显示锁/输入/接收回调中不做文件 I/O。

上限 64 个会话，每个会话 128 轮。会话达到 128 轮后下一轮新建会话；总会话满则提示删除，不静默淘汰历史。每轮原文 1536、回答 6144 UTF-8 字节，延续设备现有接收上限；长内容显示截断标记。待写队列至多八轮，存储不可用时暂存并重试，满后拒绝开始下一轮，避免悄悄丢失。断电会丢失尚未成功写入的内存内容。不得把“最近胶囊 NVS 保存成功”当成“历史已经落到 SD”。

删除采用会话目录改名为 `.deleted`，列表不再显示且编号不复用；SD 上保留恢复目录，不是安全擦除。聊天不加密，不自动上传同步其他设备；用户需要自行保护/备份 SD。仅当前会话的任务上下文会按用户操作发给所连接的小智服务。CRC 只是损坏检测，不是认证或加密。

## 首页、笔记、图标

首页“录音”替换为“笔记”，触摸和实体键都进 AI 笔记；录音功能保留在应用目录。笔记列表五行，每行 92px 间隔；标题、摘要和分隔线分别定位。详情标题放到 y=148，位于页头分隔线 y=128 之后，正文 y=212 开始，每页十行。

新增六个 Lucide 原版 SVG：delete、arrow-big-up、languages、list-todo、sparkles、message-square。和原有图标一起固定到同一个上游提交并校验 SHA-256，保留完整 ISC/Feather MIT 许可证。提前生成 24/28/32/40px 的 1-bit 图标，不在 ESP32 运行 SVG 引擎。退格/Shift、快捷操作和历史采用原版图标；保持黑白，不引入灰阶蒙层。无需刷新字体分区。

## 附件中已有的书签测试问题

原书签 NVS blob 直接使用 C++ 结构体对象，尾部 padding 未明确清零；GCC/Clang 可能生成不同尾部字节。保存前现在将整块对象表示清零并显式恢复 magic，再填字段。字段与格式未变，旧书签仍可读取。相关主机回归用两种编译器运行，不依据只在 GCC 通过便判为硬件问题。

## 验证入口

`tools/check_chat_history.py` 执行真实历史文件/队列/任务信箱；`check_ai_contract.py` 验证三项短事件、未读取任务保护、消息错误和文字重试；`check_memory_contract.py` 执行真实 MCP 工具发现与调用；`check_ui_icon_sources.py` 检查上游文件与生成位图。原音频与 ELF 内存预算必须继续通过。

`render_ui_preview.py` 包含真实 history/input/system 绘图和触摸路径，主机适配仅替代无线电/硬件操作。完整 ESP-IDF 6.0.1 build 和设备端真实 MCP、SD 拔卡、断电、堆/栈峰值仍需分别验证。更新沿用分区匹配后的 app-flash，不擦 NVS/字体/OTA。
