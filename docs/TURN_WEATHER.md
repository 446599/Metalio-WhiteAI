## 卡住的回合

附件可确认多轮没有 STT 文本，最终 state=3、原文/回答为空；翻译快捷操作并未被真正触发。README 把编码器就绪解读为上行发送成功、把 STATE busy=0 解读为没有任务运行，这两个判断不能仅由这些日志成立：前者不能证明云端收到语音，后者是屏幕刷新状态。本次不据此排除麦克风、音频发送或云端问题。

旧代码已有45秒等待超时，但释放连接、操作失效等分支会先清掉回合标志和计时器，未必同步结束 Conversation 状态。此次统一在清理前将未完成回合收尾为 Error、保存已收到内容；完成的回答不受空闲断线影响。

- 等待应用 hello 10秒、松手等待识别20秒、无有效文本/音频进展45秒，以及整轮180秒的有界检查。轮询可能受当前网络操作影响，不能当成硬实时截止时间。
- emotion/心跳不延长等待；提前到达的 STT 能被接收，并补发 manual stop，不把 Thinking 改回 Transcribing。
- 实际 WebSocket 二进制写入成功后才计数；写入失败由网络任务关闭该回合，不从采集回调释放连接。正常松手后被过滤的帧不算传输错误。
- 所有释放路径终止未完成状态；孤立的“正在识别”（没有活动回合和待处理操作）会收尾。旧连接迟到数据仍按 epoch 拒绝。
- 重连只恢复连接，不自动录音或重放用户任务。元数据 reset 记录 cause/epoch/state/active/tx_packets/tx_bytes，不打印正文或凭据。

三个快捷操作仍需要服务发现并读取 self.chat.get_task；本次没有用真实云端账号复现翻译，不承诺服务端一定返回回答。参见 CHAT_HISTORY.md。

## 天气使用

设备设置 → 天气 → 选择城市。输入中文、拼音或英文，选择带地区的结果；取得匹配地点后才存储配置，不默认把北京当作所在地，也不使用 IP 自动定位。保存失败保留原城市。

接入 Open-Meteo 的 Geocoding 与 Forecast HTTPS API：温度、体感、湿度、风速和 WMO 天气现象。单位固定为摄氏度和 km/h，显示数据提供方的时间；离线/过期/刷新失败不清空上次有效结果。城市与天气缓存分别使用单个 NVS blob，缓存还绑定请求来源，切换城市不串用旧数据。原显式配置的 HTTPS weather_url 保留兼容；首次选择城市后优先使用城市配置。

后台默认10分钟轮询（沿用 dashboard/refresh_minutes 设置），手动刷新最短间隔1分钟。休眠暂停网络请求，进行中的语音回合让天气任务延后；复用既有 dashboard 任务，不新增常驻任务栈。响应限制16KiB、HTTP超时10秒；搜索最多5个结果，有取消代次校验。具体等待还受原联网建立过程影响。

来源和使用条件：
- https://open-meteo.com/en/docs
- https://open-meteo.com/en/docs/geocoding-api
- https://open-meteo.com/en/terms

面向个人非商业使用的公共端点不要求 API key；商业部署应遵循提供方条款。页面保留 Open-Meteo 署名。搜索词/选定坐标会发送给天气提供方，不发送 Wi-Fi 密码、小智 token 或聊天内容。网络必须能访问这两个服务；不能用主机/CI测试替代用户当地网络可达性与实际设备认证。返回的是模型天气数据，不标榜为本地传感器实测。
